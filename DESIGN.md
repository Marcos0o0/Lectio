# Design System: Lectio

## Overview

**Creative North Star: "A quiet reading room"**

Lectio pairs graphite surfaces, slate layers, and soft blue actions with literary headings and clear native controls. Dark is the initial theme; explicit Claro and Sistema preferences remain available and persisted. Reading and contextual understanding share one space: tapping a word opens native Spanish Wikcionario meanings or English Wiktionary meanings and translation in a native sheet, with separate context and notes tabs; selecting English phrases opens translation. The Español/Inglés selector remembers the choice per book. Spanish meanings and vocabulary saving need no translation model or Gemini. The library asks “¿Qué te gustaría leer?” without promotional support copy. English-to-Spanish local translation needs a one-time language download; Gemini explanations stay behind explicit optional English-reading actions. Local use requires no account.

The reader adds an explicitly selected Papel palette: soft cream pages, dark brown ink, and muted olive actions continue through its native frame. This reading-only choice leaves the library and application theme independent. Reading advances one viewport page at a time, retaining text location as type and window dimensions change. Immersive reading hides app and system chrome while retaining a visible exit control and word consultation.

This is a code-led record of the native Android Compose implementation, not a reference composition. Compose dimensions use dp and text uses sp; the isolated EPUB WebView has its own CSS reading surface. Native components in the JSON sidecar are descriptive records, not HTML/CSS previews. Token frontmatter is normative; framework defaults remain owned by Material 3, and implementation limitations below are not new design rules.

**Key Characteristics:**
- Modern graphite dark surfaces, slate containers, soft blue actions, and a cool light scheme.
- Serif literary headings with sans serif functional text.
- Material 3 controls, tonal containers, and native modal sheets.
- Adjustable reading type, page and controls, with a live preview and visible Spanish/English dictionary and translation provenance.
- Sequential viewport pages, immersive reading, and an optional Papel reading palette shared by content and reader chrome.
- Four destinations that adapt from bottom navigation to a rail.

## Colors

The palette uses graphite and slate neutrals with soft blue primary actions. Both schemes explicitly define every Material 3 color role in ui/Theme.kt; the frontmatter records those assignments without deriving a replacement palette. There is no dynamic wallpaper color implementation.

Papel is an approved reader-only extension in `LectioPaper`, a copy of `LectioLight` with the explicit `*-paper` overrides recorded above. Unoverridden tertiary, inverse, error, and scrim roles retain their light-scheme values. Cream background/surface and dark brown on-background/on-surface pair with muted olive primary actions and warm brown secondary roles; matching containers color selection and saved highlights. The selected reading scheme also colors the reader top bar, page toolbar, appearance/contents/search sheets, and system-bar icon appearance. It does not replace the app palette or establish warm colors for library surfaces.

### Primary

Deep blue (primary-light) and soft blue (primary-dark) carry filled actions, reading progress, selected chapter indicators, activity values, and source labels. Their on-primary partners carry foregrounds on filled actions. The primary-container pairs provide the continuing-reading card and activity chart surface. The launcher icon uses the dark background and primary colors; the native startup window uses the same graphite background.

### Secondary

Slate blue-gray supplies the secondary roles; secondary-container distinguishes the vocabulary review summary and saved EPUB highlights. Use the foreground corresponding to the selected container. The continuing-reading card explicitly pairs its primary-container foregrounds; some summary surfaces currently inherit text rather than explicitly applying the matching container foreground.

### Tertiary

Muted violet completes the explicit Material scheme for components that request tertiary roles. It does not establish a separate promotional accent or a new screen treatment.

### Neutral

Background and surface share graphite in dark mode and cool near-white in light mode; on-background and on-surface supply the matching text. On-surface-variant carries authors, explanations, metadata, and helper copy. Outline-variant carries dividers. The five surface-container levels provide tonal layers for native components; EPUB blockquotes use surface-container. Inverse, tint, error, scrim, bright, and dim roles are explicitly recorded, rather than inherited from a warm default scheme.

**The Paired Roles Rule.** Resolve UI colors through MaterialTheme.colorScheme and use the foreground role corresponding to its background role.

EPUB selection uses primary-container / on-primary-container; saved highlights use secondary-container / on-secondary-container; dividers use outline-variant. The reader error fallback also follows the current background and foreground. The local cover-* tokens describe deterministic fallback illustrations only; they are not general UI accents.

## Typography

**Display Font:** bundled Literata (`Literary` in Compose; generic serif fallback in the WebView).
**Body Font:** Android `FontFamily.SansSerif`.
**Label Font:** Material default family; only `labelLarge` size, line height, and medium weight are overridden.

Literata display and headline roles create the literary character; sans serif titles, body text, and controls keep navigation practical. The offline variable font is bundled at `app/src/main/res/font/literata.ttf`, with its OFL license at `app/src/main/assets/fonts/OFL.txt`. The same font supplies fallback cover titles and the reader's serif option.

### Hierarchy

- **Display small:** retained in `LectioTypography`; no longer used for the library introduction.
- **Headline large:** library question, vocabulary and activity introductions, saved-word sheet heading.
- **Headline medium:** app bar titles, lookup heading, weekly reading total.
- **Headline small:** section headings, empty states, continuing-book title, word translation.
- **Title large:** vocabulary row word and saved-word translation.
- **Title medium:** book row title, settings groups, reader title, search result chapter.
- **Body large / medium / small:** introductory support, explanations, metadata respectively; use the frontmatter's distinct leading.
- **Label large:** calls to action, progress text, and continuing-reading context. Unoverridden label roles retain Material defaults.

**The Two Reading Voices Rule.** Use the Compose type roles for app UI; allow the separate reading page to follow the reader's serif/sans, size, and line-height preferences.

The EPUB page defaults to bundled Literata / generic serif, size (20 CSS px), and line height (1.8), with sans serif as the alternate. Controls permit size (16–32 CSS px) and line height (1.4–2.2). WebView `textZoom` follows the Android system font scale, so these preference values scale with the OS. The reader font is bundled at `app/src/main/assets/fonts/literata.ttf` and served from an intercepted local URL without network access. WebView h1 uses (1.8em), regular weight and leading (1.2); h2 uses (1.25em) and leading (1.35). Heading separation uses h2 top padding (1em), bottom margin (.7em), and `display: flow-root` to keep adjacent paragraph margins from collapsing into the heading.

## Layout

The app has four persistent destinations: Biblioteca, Vocabulario, Actividad, and Ajustes. Below (600dp) available width they use a bottom `NavigationBar`; at or above that width they use a `NavigationRail`. Both show labels. Opening a book replaces destination navigation with the reader top bar and progress/chapter toolbar; immersive mode hides both toolbars, the gesture hint, and system bars, reserving space above the reading text for its visible exit control.

Lists and settings use the `screen-inset` token. Common list spacing is `gap-section`; card interiors use `card-padding`; related controls use `gap-small` and `gap-medium`. Empty states use the wider `empty-inset` and `empty-vertical` spacing. Modal sheets use the screen inset with `sheet-bottom` bottom padding. `FlowRow` wraps library filters, vocabulary filters, settings theme and reading choices, and AI actions. Settings separate application appearance from Lectura, Diccionario y traducción, and Gemini. Reading preferences share Texto, Página, and Controles tabs in settings and the fully expanded, scrollable reader appearance sheet.

The continuing-reading card pairs a cover (98 × 148dp) with a flexible text column. Library rows use covers (72 × 108dp), a flexible title/metadata column, and a native overflow action. These are observed component dimensions, not a universal grid. Expanded screens currently retain a single main content column; the rail does not imply a tablet multi-pane layout.

The EPUB page is centered with maximum body width (740 CSS px), effective top padding (20 CSS px), bottom padding (24 CSS px), and selectable side margins (12, 28, or 44 CSS px; default 28). A fixed viewport clips a single page of a fixed-height, multi-column content container. Its column width is the centered body width minus the chosen side margins; the column stride is the WebView viewport width. Usable column height subtracts the top and bottom padding. Paragraph spacing is selectable (.5, 1, or 1.5em), with optional justified alignment. Images fit the content width and usable page height; tables scroll horizontally and preformatted text wraps. There is no established character-count measure. The lookup body scrolls between a fixed word/pronunciation/close header, stable tabs, and the save footer when an English translation or Spanish dictionary meaning can be saved; compact height intentionally reduces the visible body.

**The Navigation Width Rule.** Use the existing compact bar / expanded rail boundary; do not copy the compact bar onto the expanded layout.

Insets are managed across native scaffolds and activity setup, with a reader navigation-bar inset. The library Scaffold consumes the bottom safe-drawing inset, keeping the import FAB above the taskbar on expanded windows. The seventeen Android 15 emulator captures in `.impeccable/review/v050` cover Spanish and English lookup, immersive reading, phone, expanded window, landscape, Papel/light/dark readers, and 130% text; they do not establish physical Redmi hardware or full keyboard/gesture coverage. See VALIDATION.md for evidence and limits.

## Elevation & Depth

Tonal surfaces provide most of the visual structure. The continuing-reading card and review/activity summaries use colored containers; dividers use the outline variant. Native FABs, menus, dialogs, bottom sheets, and buttons retain Material 3 default elevation and state behavior. There are no custom shadow, elevation, or motion token definitions to export. Do not invent CSS shadows or bespoke hover transitions for native controls.

## Shapes

The continuing-reading card has the explicit `resume-card` radius. Book covers have the asymmetric `book-cover` corners, with a narrower left edge suggesting a spine. Other surfaces use `MaterialTheme.shapes.large` or `.medium`; chart bars use `.small`. `LectioTheme` does not override Material 3's shape system, so those dimensions remain framework defaults. Buttons, chips, fields, dialogs, and sheets likewise keep their component shapes.

## Components

### Buttons

Filled `Button` is used for saving vocabulary and configuration; `FilledTonalButton` for review and saving a highlight; `OutlinedButton` for optional Gemini connection and personal meaning/translation save; `TextButton` for retry, lower emphasis actions, disclosures, reset, and dialog choices. Most form actions fill available width. Icons, selected/loading/disabled behavior, ripple, focus, and touch targets come from Material 3, without custom web hover styling. The import action is one extended FAB with primary/onPrimary colors and a progress indicator while importing.

### Chips

`FilterChip` expresses selected library/vocabulary filters, application theme, reading font, page background, margins, paragraph spacing, and the per-book Español/Inglés lookup language. `AssistChip` expresses explicit Gemini explanation, grammar, and simpler-English actions and is disabled during lookup loading. Spanish linked definition terms use `SuggestionChip` to start a related-word consultation. Their colors, borders, state layers, and shapes retain Material defaults. Wrap groups using the existing `FlowRow` patterns where space varies.

### Cards / Containers

The continuing-reading card uses the explicit paired primary-container foregrounds, card inset, cover, textual status, linear progress, and forward icon. Vocabulary review uses a secondary container; activity uses a primary container. These are tonal highlights, not a rule to put every row into a card. Library entries are plain clickable rows; vocabulary uses `ListItem` and thin dividers.

### Inputs / Fields

Search, API setup, personal meaning/translation, and notes use `OutlinedTextField`. Search is single line; personal meaning/translation allows up to four lines and lookup notes up to five. The optional connection key has native password transformation and a visibility icon. The inline Gemini connection form is disclosed by an outlined action; provider, model, and endpoint fields stay under advanced options. Selection/context sharing, account usage, and encrypted local key storage are disclosed before saving the connection. Settings validation appears as separate error-role text, not a custom error border system. Field focus, cursor, border, and disabled treatment remain Material defaults.

### Navigation

`TopAppBar` gives screen context, with headline-medium titles outside the reader. The reader uses a compact title and chapter subtitle, back, search, appearance, contents, previous/next page, progress, and bookmark controls. A fullscreen toolbar action enters immersive reading. Its footer says “Página N de M” and “del capítulo” alongside the approximate book percentage; while layout is pending it says “Preparando páginas…”. The page arrows disable at the beginning and end of the book. The contents index retains explicit chapter jumps. Bottom navigation and rail share the same four labeled destinations. `PrimaryTabRow` separates contents and annotations, lookup Significado (or Texto for Spanish phrases / Traducción for English phrases) from Contexto and Notas, and reading preferences into Texto, Página, and Controles. Settings subpages have a native back action. Opening optional Gemini settings from lookup uses a full-screen native dialog; back returns directly to the same open book. Transient feedback uses the `SnackbarHost` of the scaffold that owns the screen's bottom bar or FAB, keeping feedback above those controls. Deletion uses an `AlertDialog`. Back dismisses lookup first, then exits immersive mode, then closes the book.

### Book Covers

Real EPUB cover images crop to the cover bounds. Missing covers get a deterministic muted color, serif title, author or demonstration text, and a dark translucent spine. Color choice comes from four cool blue/slate/violet local constants (cover-blue, cover-violet, cover-teal, cover-slate). Titles use cover-title, metadata uses cover-metadata, and the 5dp spine uses cover-spine. These illustration tokens are not a primary-action palette. Tiny uppercase edition labels in this fallback are an existing implementation defect, not a reusable eyebrow/kicker pattern.

### Meaning Sheet

Tapping a word or selecting text opens `LookupSheet`, a fully expanded `ModalBottomSheet`. Its word heading, optional pronunciation, language-appropriate speech/close controls, and tabs stay above the scrollable body; a save action stays below when an English translation or Spanish dictionary meaning is available for selections up to 12 words. Significado (Texto for Spanish phrases, Traducción for English phrases), Contexto, and Notas separate the tasks. The meaning body starts with Español/Inglés `FilterChip` choices under “Idioma del texto”; correcting the detected language is remembered per book. English word translations use headline-small; phrases use body-large and show the selected text above.

Spanish words show original Spanish Wikcionario senses without translation, a translator download, or Gemini. English words retain local translation and real English Wiktionary definitions; those definitions are translated locally when the model is available, with optional English-original disclosure. Both paths show grammatical categories, examples when available, two senses initially, additional-sense disclosure, entry/license links, and separate dictionary loading/error/retry/cache states. Entries provide up to four senses; Spanish inflections can follow one explicit lemma link and show up to five combined senses. Spanish entries identify the consulted spelling, label the base form when available, link its source, and offer linked definition terms as related-word consultation chips. Definitions use body-large; grammatical labels use label-large in the primary role, and examples/credits use quieter body roles. Cached entries remain separate by language. Spanish vocabulary saves the dictionary meaning independently of translation; saved meanings retain the corresponding Wikcionario/Wiktionary attribution and CC BY-SA 4.0 license link.

English-to-Spanish Google ML Kit translations carry the official, unmodified theme-appropriate Google Translate badge and on-device attribution. First use offers a one-time Spanish download, Wi-Fi by default with an explicit mobile-data choice, progress, errors, and retry. Contexto shows the original sentence and, for English, its translation and optional Gemini explanation actions with account-usage disclosure; generated results identify their source and possible AI errors. A contextual explanation can also appear in the meaning tab after generation. Notas contains selected text, a note field, highlight save, and a personal meaning for Spanish or translation for English when no translation result exists. Optional Gemini setup opens native settings and returns to the same book. The sheet remains part of the reading flow and requires no account.

### Reading Surface

An isolated WebView renders reflowable content using the chosen reading background/foreground, bundled Literata or sans serif, reader preferences, and OS text scaling. The reading scheme can follow the app or independently use Papel, Claro, or Oscuro, and applies to both content and reader chrome. A tap selects a word when enabled; long press uses native selection. Both feed the language-aware lookup sheet through the touch/selection bridge, and native selection adds a “Consultar” action as a fallback. Saved highlights are applied to page text. The normal native frame keeps chapter context and progress visible. Immersive mode hides that frame, the gesture hint, and system bars. A visible top-right exit `IconButton` has a 48dp target; a reserved 56dp top area keeps reading text clear of it. Cutout insets remain respected. Swiping and word consultation remain available, lookup temporarily restores system bars, and exit restores the normal frame while preserving the text location. Back dismisses lookup first, then exits immersive mode, then closes the book. Selection and saved highlights use paired theme container roles, blockquotes use the surface container, and dividers use the theme outline variant. The error HTML fallback uses the same background and foreground as the reading page.

Page buttons, horizontal swipes, and WebView ArrowLeft/ArrowRight or PageUp/PageDown keys call the same single-page turn. Only a chapter boundary requests another chapter: advancing opens its first page, and reversing opens the previous chapter's last page. A nonempty text selection suppresses page turns. The engine waits for the bundled font and initially settling images, then recalculates after window resizing or later image loads. These are viewport pages within the current chapter, recalculated for the selected type, margins, and window; there is no whole-book page total or equivalence to printed page numbers.

The reader saves text offsets in the sanitized chapter and restores their containing page across typography, margins, theme, rotation, and reopen. Bookmarks and annotation locations carry that offset too. Legacy positions and image-only content retain a fractional fallback; offsets are not portable CFI locators. Search highlights and opens the matching page, while internal links resolve their target fragment. Saved highlight text still uses its first exact match, an existing limitation rather than a stronger annotation-anchor guarantee.

Reading preferences show a live native preview using the selected font, size, line height, background, margins, paragraph separation, and alignment. Texto owns typography; Página owns background and spacing; Controles owns tap consultation, keeping the screen on, and the gesture hint. Full-row native switches expose each control. Restablecer lectura resets these reading preferences while preserving application theme, books, and connection credentials.

## Do's and Don'ts

### Do:

- **Do** use Material 3 color roles with matching foregrounds in both explicit schemes.
- **Do** use serif headline roles and sans serif functional type through `LectioTypography`.
- **Do** retain the compact navigation bar and expanded navigation rail behavior.
- **Do** keep reading preferences separate from app UI typography.
- **Do** apply the selected reading scheme to page content and reader chrome while retaining the independent application theme.
- **Do** turn one viewport page per navigation action and identify page counts as relative to the current chapter.
- **Do** preserve visible dictionary/translation provenance, language-aware lookup, one-time English-translation download choices, and explicit optional explanation actions in the reading context.
- **Do** retain the visible immersive exit target and reserved text space; Back dismisses lookup before exiting immersive reading or closing the book.
- **Do** use native Material controls and their built-in interaction states.

### Don't:

- **Don't** treat fallback cover colors as general app accents or apply the reader-only Papel palette as a global warm rebrand; warm reader colors belong to its explicitly selected paired roles.
- **Don't** promote tiny uppercase cover labels into a reusable heading pattern.
- **Don't** describe framework defaults as custom Lectio shadow, shape, motion, or error tokens.
- **Don't** introduce account UI as a prerequisite to local reading or vocabulary.
- **Don't** present Android 15 emulator touch/long-press or DOM phrase-selection tests as physical-phone, selection-handle, TalkBack, live Gemini, TTS, or performance verification.
